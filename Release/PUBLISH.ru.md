# Публикация Reels While GPT 1.16

Подготовлено 8 октября 2026 года. Текущая .app — локальная ad-hoc сборка с Hardened Runtime. Она не подписана Developer ID и не нотарифицирована. Нельзя обозначать её как одобренную Apple или «полностью готовую для Mac App Store».

## Будущий выпуск с Developer ID: сайт или страница релизов

Apple допускает самостоятельное распространение macOS-приложений через Developer ID и нотарификацию. См. [распространение macOS](https://developer.apple.com/macos/distribution/), [Developer ID](https://developer.apple.com/developer-id/) и [нотарификация](https://developer.apple.com/documentation/security/notarizing-macos-software-before-distribution).

1. Зарегистрировать/подтвердить Apple Developer Program на имя издателя. Цена у Apple — 99 USD в год, местная цена/доступность могут отличаться: [регистрация](https://developer.apple.com/help/account/membership/program-enrollment/). Вход в Apple Account и принятие соглашений выполняет владелец.
2. Выбрать имя издателя, постоянный идентификатор вида `com.yourcompany.reelswhilegpt`, контакт поддержки, место скачивания. Нельзя менять идентификатор при каждом обновлении. Текущий локальный `local.ReelsWhileGPT` оставлен для тестовой сборки; окончательный ID нужно выбрать перед первым публичным выпуском. Смена ID создаёт отдельные настройки, разрешения и хранилище WebKit; вход потребуется выполнить заново. Приложение не копирует токены из старого ID автоматически.
3. Создать Developer ID Application certificate и хранить закрытый ключ в macOS Keychain. Не отправлять пароль Apple Account, закрытый ключ или app-specific password в чат/исходники. Создать профиль `notarytool` в Keychain локально согласно документации Apple. Скрипт использует только имя профиля, не секретные параметры.
4. Выполнить локальные тесты, затем собрать с сертификатом. Скрипт включает Hardened Runtime, разрешение Apple Events и privacy manifest. Используются только Apple frameworks, без сторонних SDK.
5. Проверить подпись и подписанную сборку на тестовом профиле. Отдельно проверить согласия AX/Automation для приложения и bundled ScriptRunner. Не добавлять обходы TCC, `get-task-allow` или отключение library validation, если что-то не работает; диагностировать причину.
6. С явного разрешения издателя отправить ZIP в Apple на нотарификацию, дождаться `Accepted`, прикрепить ticket к .app, проверить `stapler` и Gatekeeper. Отправка передаёт Apple бинарники приложения, не Instagram cookies пользователя: в ZIP включён только app bundle.
7. Проверить скачанный ZIP на чистом Mac с атрибутом quarantine. Из архива должна запускаться та же версия, с подтверждённым издателем и исправной подписью. Проверить сохранение/удаление входа, автоматический детектор, другие окна, свайпы, мини-шкалу и размер окна. Не выдавать локальные unit-тесты за этот прогон.
8. Опубликовать нотарифицированный ZIP, контрольную сумму SHA-256, описание, требования (Apple Silicon, macOS 13+), инструкции разрешений, поддержку и политику конфиденциальности. Добавить настоящие сведения об издателе в `PRIVACY.*.md`. Сохранить в выпуске файл LICENSE; Лицензия: PolyForm Noncommercial 1.0.0; см. LICENSE и NOTICE. Не использовать чужие видео/переписку и данные аккаунта в рекламных скриншотах.

### Готовые команды

Сначала закончите настройку Apple Developer/Keychain. В терминале из корня проекта:

```bash
export CODE_SIGN_IDENTITY='Developer ID Application: YOUR LEGAL NAME (TEAMID)'
export RELEASE_BUNDLE_ID='com.yourcompany.reelswhilegpt'
./Release/distribute.sh prepare
```

Это только локальная сборка/подпись. Команда не отправляет данные Apple и не публикует файл. Затем — только когда вы разрешаете отправку бинарника Apple:

```bash
export NOTARY_PROFILE='YOUR_EXISTING_KEYCHAIN_PROFILE'
./Release/distribute.sh notarize
```

Результат: `dist/ReelsWhileGPT-arm64.zip`, `dist/SHA256SUMS.txt`, `dist/notarization-status.plist`. Скрипт прекращает работу, если Apple не вернула Accepted. Он не загружает релиз на сайт. Xcode и его лицензия должны быть настроены владельцем машины; реальный Developer ID/нотарификация в этой сессии не выполнялись.

## Mac App Store

Текущая сборка не использует App Sandbox. Для магазина Apple требует sandbox в [пункте 2.4.5](https://developer.apple.com/app-store/review/guidelines/). Это отдельная работа по архитектуре, signing/packaging и тестированию AX/Automation в sandbox, а не переключатель в инструкции. При невозможности поддержать требуемую интеграцию нужно изменить объём функций; не обещать прежний нативный детектор без проверки.

После адаптации потребуются App Store Connect, сведения об издателе/приложении, публичные privacy/support URLs, реальные скриншоты без чувствительных данных, корректный возрастной рейтинг и описание стороннего веб-контента, privacy questionnaire с учётом содержимого Instagram, доступный reviewers сценарий демонстрации и проверка прав на интеграцию/бренд. Apple отдельно регулирует использование сторонних сервисов (п. 5.2) и минимальную функциональность (п. 4.2). Решение о прохождении ревью принимает Apple; одобрение не гарантируется.

`PrivacyInfo.xcprivacy` описывает нативный код утилиты: отсутствие собственной телеметрии и использование UserDefaults для локальных настроек (`CA92.1`). Это не утверждение, что встроенный сайт Instagram не обрабатывает/не отслеживает данные. Перед App Store submission нужно отдельно сверить privacy questionnaire и manifest с актуальным поведением интегрированного веб-контента. См. [privacy manifests](https://developer.apple.com/documentation/bundleresources/privacy-manifest-files) и [required reason API](https://developer.apple.com/documentation/bundleresources/describing-use-of-required-reason-api).
