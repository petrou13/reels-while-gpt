# Бесплатная публикация на GitHub

Автор: petrou13. Планируемый репозиторий: `petrou13/reels-while-gpt`.

Публичный репозиторий можно разместить на GitHub Free. Платный аккаунт Apple Developer для этого не нужен. [Условия GitHub](https://docs.github.com/en/repositories/creating-and-managing-repositories/about-repositories).

## Что подготовлено

Исходники, английский/русский README, оригинальная PolyForm Noncommercial 1.0.0, NOTICE автора, правила участия/сообщений о безопасности, политика конфиденциальности, тесты, сборка и GitHub Actions. Личные настройки, вход Instagram, cookies, сертификаты/ключи и рабочая история чата не входят в публикацию.

GitHub Actions закреплены на проверенных commit SHA официальных actions. Обычный CI имеет только чтение репозитория, не получает секреты Apple и не публикует релизы. Отдельный workflow запускается вручную только с main и публикует тестовый prerelease с временным GITHUB_TOKEN, который выдаёт GitHub. Этот токен не записывается в исходники; выражение `${{ github.token }}` — ссылка на токен платформы, а не секрет.

## Первый шаг владельца

Если репозиторий ещё не существует, создайте **public** `reels-while-gpt` в аккаунте `petrou13`: [создать репозиторий](https://github.com/new?name=reels-while-gpt&visibility=public). Можно создать с README, чтобы у main появился первый commit. Не выбирайте MIT/Apache/GPL — полный LICENSE уже подготовлен. Если соединение Codex ограничено выбранными репозиториями, добавьте новый репозиторий в доступ GitHub App. Подключённый инструмент умеет записывать файлы в доступный репозиторий, но не предоставляет создание самого репозитория.

После создания исходники можно загрузить через подключение Codex либо GitHub Desktop. Не загружайте всю рабочую папку Codex. Используйте отдельную подготовленную папку проекта/архив. Перед записью в непустой репозиторий требуется сверить существующие файлы и не перезаписывать чужую работу.

## Автоматическая сборка и бесплатный бинарный выпуск

После публикации main откройте Actions → Test and build. При успешном завершении там будет ZIP локально подписанного приложения и контрольная сумма. Workflow на GitHub в этой среде ещё не запускался.

Когда хотите опубликовать бесплатный бинарный выпуск: Actions → Publish free test prerelease → Run workflow на main. Он сначала проверяет/собирает приложение, затем создаёт prerelease `v1.16` с ZIP и SHA-256. Первый запуск возможен только после размещения файлов workflows в GitHub; не заявляйте об опубликованном релизе до его успешного окончания. Повторный запуск с тем же тегом не перезаписывает существующий релиз; увеличьте версию для нового выпуска.

Сборка не проходит нотарификацию и macOS может её блокировать. На странице релиза это явно указано. Пользователь может собрать исходники на своём Mac или применить доступное точечное «Всё равно открыть» по [инструкции Apple](https://support.apple.com/102445), если доверяет сборке. Не отключайте Gatekeeper/SIP. Распространение исходников бесплатно не делает приложение одобренным Apple.

## Безопасность и поддержка

Включите в настройках репозитория private vulnerability reporting, если хотите принимать приватные отчёты. Политика конфиденциальности и поддержка могут ссылаться на файлы репозитория и Issues — отдельный платный сайт не требуется. Не публикуйте личные скриншоты, дампы cookies, токены и коды подтверждения. Коммерческое использование не разрешено по лицензии; само наличие публичного GitHub не меняет этого условия.

План Developer ID/нотарификации сохранён в PUBLISH.ru.md на будущее. Сейчас отсутствие денег на членство Apple Developer не мешает открыть исходники и подготовить бесплатный prerelease с честным обозначением ограничений.
